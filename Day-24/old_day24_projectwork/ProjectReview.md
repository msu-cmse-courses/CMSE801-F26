## Plan for presentations 

The following is a template for how to run discussions within your group.  You need not follow this to the letter as some projects will do better with different styles of discussion. 

### Part 1: General Project Feedback

For this part, you will present the current state of your project to a classmate. You can present any slides you might have, walk them through your notebook, or generally try to give some version of your final presentation (~5 minutes). After you "present" you will receive feedback.

When **listening** to a presentation you should be thinking about the following questions and be prepared to discuss them with the presenter:

1. What part(s) of project did you find particularly interesting and why?

2. What part(s) of the project were your confused by or didn't entirely understand and why?

3. What recommendations do you have for the presenter that might improve the project or their final presentation?

### Part 2: Code Review

For this part, you're going to actually review any code that has currently been written to support the project. While reviewing the code, you should be looking for the following:

1. Is the code easy to read/follow? (e.g. do the variable names makes sense? Is there any unnecessary code or commented out code?)
2. Is the code modular? That is, are functions or classes use to simplify the "main" parts of the code and reduce the need for redundant code?
3. Is the code well-documented/commented?
4. Does the code appear to run correctly, even if the notebook is restarted and all of the current output is cleared? (Be careful here! If the code takes a long time to run, you don't need to test it right now).

**Provide any and all feedback to your classmate**.
